# 資產配置管理工具（asset-lab）

個人用的資產配置與報酬率管理工具。每月手動輸入各項資產的市值與當月淨投入，工具計算**排除資本流動後的真實報酬率**、視覺化資產配置與淨值變動，並支援負債與目標配置管理。不串接任何行情／財報／券商 API，金額一律手動輸入。

核心難點在報酬率：使用者每月會手動增減本金，單純比較「期末 ÷ 期初」會把新投入的錢誤算成報酬。本工具以「市值＋當月淨投入」兩欄記錄，計算時排除資本流動，提供 TWR、MWR、簡單總報酬率三種口徑。股票／ETF 類項目則直接照抄券商 App 上的「目前總成本」與「現值」（有賣出或領股利時再照抄已實現損益與現金股利），當月淨投入由工具自動推算，免去每月手算。

另針對大跌時的行為紀律，工具內建「大跌行為協定」：以累積 TWR 自歷史高點的回撤幅度判斷目前處於平時／修正／熊市／深熊哪個情境，登入後的總覽頁主動顯示對應的必做／禁止摘要，把「翻文件提醒自己」的自律負擔改由系統承擔。

另針對購屋規劃，工具提供「買房」頁：依家庭稅後月收反推可負擔房價、依目標房價正算月付負擔，追蹤自備款準備金（bucket）累積進度與組成健康度（是否混入非活存／定存的波動資產），並以五條觸發條件（三項系統判定＋兩項主觀勾選）檢核購屋時機是否成熟；總覽頁同步顯示進度摘要。

## 功能

- 月度資料錄入：以 (年月, 項目) 為粒度記錄市值與當月淨投入；錄入月份以年＋月下拉選擇、預設帶入當月；新月份自動帶入上月仍持有項目，只需更新數字；支援新增／編輯／刪除單列與「項目間轉移」成對輸入。選定項目與月份後，錄入框帶入該月既有值（回頭修改時不會把其他來源寫入的數字蓋成 0）；該月尚無紀錄時，市值（股票／ETF 為總成本與現值）留空、須填寫才能存檔。台股／美股（含 ETF）項目改填目前總成本、現值、本月已實現損益（可為負）與本月現金股利（不可為負），存檔前先顯示推算出的當月淨投入供核對，欄旁並提示賣出款項或股利存入有追蹤的帳戶時須另做項目間轉移。項目間轉移在非股票端累加淨投入、保留既有市值，同月多次轉移逐次累加；股票／ETF 那一端不寫淨投入（由總成本推算）。頁面下方顯示「本月已存紀錄」唯讀表格（存檔或轉移後即時更新），市值空白的列提醒尚未填。
- 金額輸入：全站金額欄（月度錄入、項目間轉移、設定頁的初始市值／初始成本與買房金額參數）以整數千分位顯示並放大；輸入接受有或無千分位逗號、全形數字，小數四捨五入為整數，逗號分組錯誤（如 `1,00,000`）、非數字或清空時拒絕存檔。百分比、年份、利率等非金額欄不變。
- 持有項目主檔：以穩定 ID 識別項目（改名不斷裂歷史報酬連乘），每個資產項目歸屬一個分類（含活存／定存／台股／美股／保險等）並記初始市值與初始成本；活存／定存新增或編輯時初始成本自動帶入初始市值（可手動覆蓋）；既有項目可就地編輯改名／改分類／改初始值。資產項目可另標記用途（一般／購屋），供買房自備款 bucket 判斷是否計入；負債項目無此欄位（bucket 僅計資產）。
- 負債與淨值：負債項目每月記餘額，淨值＝總資產 − 總負債；負債排除於配置佔比與報酬率之外。
- 報酬率計算：TWR（時間加權）、MWR（XIRR 金額加權）、簡單總報酬率（相對成本）三種，加上絕對賺賠金額，可拆整體／分類／單一標的三維度；計算區間可選（自開始記錄以來／YTD／近一年／自訂）。
- 配置視覺化：單月資產佔比圓餅圖、配置佔比隨時間漂移的堆疊面積圖、淨值趨勢折線（可疊加總資產／總負債）、累積 TWR 走勢折線。
- 目標配置：設定各分類目標比重，顯示現況對目標的偏離，超過門檻提示再平衡。
- 大跌行為協定：登入後總覽頁顯示目前協定等級（L0 平時／L1 修正／L2 熊市／L3 深熊）、該等級必做／禁止摘要與關鍵指標（累積 TWR、淨值、目前回撤%）；等級門檻可於設定頁調整並持久化；另有唯讀頁完整呈現協定全文（`docs/PROTOCOL.md`）。
- 購屋規劃：「買房」頁提供可負擔性雙向試算（依月收反推可負擔房價／依目標房價正算月付負擔）、自備款準備金（bucket）累積進度與非活存／定存資產混入的組成警示、五條購屋觸發條件檢核（三項系統判定＋定錨／認知兩項主觀勾選，勾選即時持久化）；總覽頁同步顯示 bucket 進度與觸發達成數摘要。個人化參數（月收、房價、年份等）預設中性 0，未設定時不誤判達標（fail-closed）。
- 資料保全：CSV 匯出與匯入還原（成對），持有項目主檔的用途標記、月度紀錄的總成本、已實現收益與現金股利隨匯出入保留（舊格式 4 欄或 6 欄 CSV 缺這些欄位仍可匯入，視為未填）；還原僅支援空庫（避免污染既有資料）。

## 系統架構與流程

採分層架構，相依方向單向（Page → Service → Repository → Model）；Service 為純運算、不碰 I/O 與 Streamlit，故可獨立單元測試。

1. `app.py` 入口：登入守門（未登入顯示登入入口、非本人顯示拒絕，皆停止後續渲染）→ 組裝依賴容器（連線與建表就緒，連線失效時自動清快取重連重試一次）→ `st.navigation` 多頁路由，登入後預設落地頁為「總覽」。
2. 各 `views/` 頁面為 View／Controller：讀使用者操作 → 委派 Service 運算 → 經 Repository 存取 Turso → 以 Plotly 呈現。頁面路由僅由 `app.py` 的 `st.navigation` 註冊——資料夾刻意不命名為 `pages/`，因該名稱是 Streamlit 保留字，會觸發框架自動多頁探索，使子頁可繞過登入守門直接以 URL 存取。
3. `services/` 純運算：報酬率三管線、配置／淨值／漂移、目標偏離、月度錄入整形（含錄入框帶入值與本月已存紀錄彙總）、CSV 匯出入驗證、大跌協定等級判定（`ProtocolService`）、買房可負擔性雙向試算（`AffordabilityService`）、自備款 bucket／組成警示／五條觸發條件判定（`HouseService`）、股票／ETF 由總成本推算淨投入與連動重算及轉移過濾（`CostBasisService`）。金額千分位的解析與格式化為 `core/utils` 純函式，輸入元件 `amount_widget.py` 以帶 key 的容器包住 `st.text_input`（原生 `number_input` 無法顯示千分位），並由 `app.py` 注入只命中金額欄的放大樣式；帶入值只在切換項目／月份（資料來源改變）時重新填入，來源不變時保留使用者尚未存檔的輸入。
4. `repositories/` 以 `libsql` 連 Turso，六張表（持有項目主檔、月度紀錄、目標配置、協定回撤門檻、買房參數、主觀觸發勾選），月度紀錄以 (holding_id, year_month) 複合主鍵保證同月同項目唯一；`ensure_schema` 對既有庫以 `PRAGMA table_info` 探測後條件式 `ALTER TABLE` 補欄位（如 holdings 的 purpose、月度紀錄的 total_cost／realized_income／cash_dividend），新庫則直接建表，兩路徑皆冪等；月度紀錄的多列寫入（存檔連帶重算後續月份、刪除連帶重算）在單一交易內完成，任一步失敗即整批 rollback；項目間轉移以 `INSERT ... ON CONFLICT DO UPDATE` 在既有淨投入上原子累加，不覆寫市值；另有 `ProtocolDocRepository` 以 `__file__` 錨定路徑唯讀讀取 repo 內 `docs/PROTOCOL.md`。

### 關鍵邏輯：報酬率口徑

報酬率的正確性是本工具的核心，三種口徑的「起算基準」嚴格分工，不可混用：

- **TWR／MWR（%）以「初始市值」起算** — 衡量開始記錄後的投資績效。TWR 逐月以 `(期末市值 − 當月淨投入 − 期初市值) ÷ 期初市值` 連乘排除資本流動；MWR 以 pyxirr 解現金流年化內部報酬率，不收斂時降級不拖垮其他指標。
- **絕對賺賠金額與簡單總報酬率以「初始成本」起算** — 含記錄前歷史。累積成本＝初始成本＋Σ後續淨投入；賺賠＝市值 − 累積成本；簡單總報酬率＝賺賠 ÷ 累積成本。
- 之所以分工：若把記錄前的成本到現值價差塞進第一期，會讓 TWR/MWR 失真。介面以函式簽名強制隔離（TWR/MWR 管線拿不到初始成本，反之亦然）。

其他規則：未滿 12 個日曆月的區間只顯示累積報酬、不年化；缺月以相鄰有資料月分段連乘、不補插；某月市值留空＝沿用上一有值月份；賣出當月記市值 0＋提領淨投入、之後缺列＝不再持有；外幣資產由使用者換算為 TWD 輸入，報酬率因此內含匯率波動（看台幣淨值，為刻意取捨）。

### 關鍵邏輯：股票／ETF 以總成本推算淨投入

券商 App 顯示的是「目前總成本」與「現值」而非當月淨投入，因此台股／台股ETF、美股／美股ETF 兩分類改填總成本、現值、本月已實現損益與本月現金股利，由 `CostBasisService` 推算當月淨投入後寫回原本的淨投入欄——下游報酬率、淨值、配置的計算口徑完全不變。

- **公式**：當月淨投入 ＝（本月總成本 − 前期總成本）− 本月已實現損益 − 本月現金股利。兩格分開照抄（損益照抄券商 App、可為負；股利照抄入帳通知、不可為負，負值拒絕存檔），平常皆為 0。必須扣除的原因：賣出時券商總成本只減少「賣出股數的成本」，實際拿回的是「賣出實收」，兩者差額不扣除的話，已實現損益會從報酬率中消失；現金股利同理是拿回的現金。
- **前期總成本**：取該項目上一筆紀錄所填的總成本；尚無任何紀錄時用主檔初始成本；上一筆是本功能上線前的舊制紀錄（未填總成本）時，以「初始成本＋之前所有淨投入」估算，錄入頁會提示這是估算值。
- **清倉**：總成本與現值皆填 0、已實現損益照實填，推算結果即為「−賣出實收」；之後月份沿用「缺列＝不再持有」語義。
- **連動重算**：修改或刪除某月紀錄後，往後掃描並重算受影響的新制紀錄（通常就是下一筆；中間夾著舊制紀錄時會一路找到第一筆新制紀錄），與存檔列在同一交易內寫入。
- **項目間轉移**：股票／ETF 那一端不寫入淨投入，只記另一端（例如買股時只記活存 −X）；兩端皆為股票／ETF 時不寫任何紀錄，以提示告知屬正常情況。賣出款項或股利存入工具內有追蹤的帳戶（如活存）時，須另做一筆「股票→活存」轉移記錄活存端，否則整體報酬率會重複計入；存入未追蹤的帳戶則不需轉移。
- 總成本、已實現收益與現金股利另存於月度紀錄（`total_cost`／`realized_income`／`cash_dividend`，舊資料為空值），供推算前期總成本、連動重算與錄入框帶回使用。`realized_income` 存兩格合計（相容既有欄位，未改名是因本機與雲端共用同一個資料庫），已實現損益＝合計 − 現金股利；本功能上線前的舊紀錄整筆視為已實現損益、現金股利為 0。

### 關鍵邏輯：項目間轉移累加與錄入框帶入值

- **累加寫入**：轉移寫入非股票端時，在該月既有淨投入上加減轉移金額、既有市值保持不變；同月多次轉移逐次累加。因此「先單列錄入餘額、再轉移」與「先轉移、再單列錄入」結果相同（例：活存 5 月先錄餘額 35 萬，再轉出 10 萬、5 萬 → 市值 35 萬、淨投入 −15 萬）。
- **尚無紀錄的月份**：轉移會建立一筆只有淨投入、市值留空的紀錄；市值留空沿用既有語義（報酬率沿用上一有值月份、淨值與配置不計入），本月已存紀錄表會提醒補錄。
- **打錯更正**：不提供撤銷，以一筆反向轉移抵銷，或用單列錄入（會帶入既有值）直接改淨投入。
- **錄入框帶入值**：選定項目與月份後帶入該月既有值（一般：市值、淨投入；股票／ETF：總成本、現值、已實現損益、現金股利），存檔後頁面重新整理，表格與錄入框即時反映最新資料。

### 關鍵邏輯：大跌行為協定等級判定

工具無任何行情 API，因此「大盤回撤」以使用者自身投組的**累積 TWR 成長指數**自歷史高點的回撤幅度當 proxy（不用淨值序列，因淨值會混入資金進出與負債變動而失真；累積 TWR 天生排除資本流動，且與 `docs/PROTOCOL.md` 本身「看累積 TWR 走勢」的指示一致）。歷史高點計算納入起始基準 1.0，避免只跌不漲的投組低報跌幅。

- 四級門檻預設 L1 −10%／L2 −20%／L3 −30%（正幅度百分比），回撤深度達門檻即進入該級（含邊界）；可於設定頁調整，並強制驗證 0 < L1 < L2 < L3。
- 累積 TWR 有效月數少於 3 個月時視為資料不足，一律退回 L0 平時姿態、不誤報大跌，且區分「尚無資料」與「資料不足」兩種文案。
- 各等級的必做／禁止摘要在程式內以結構化常數編碼（依 `docs/PROTOCOL.md` §1 表謄寫）；「只看本系統、不看券商 App」等行為防火牆提醒僅在 L1 以上（真的偵測到下跌）才顯示，L0 平時維持乾淨、不冗贅提醒。

### 關鍵邏輯：買房可負擔性與觸發條件

- **可負擔性雙向試算**：反推方向（依家庭稅後月收 × 月付上限比率算可負擔月付、再依驗算利率與貸款年限反推可負擔總價）與正算方向（依目標總價算所需月付、除以月收得月付占比）共用同一套年金公式。月收未設定（0）時反推方向回傳 `None`，畫面顯示「未設定」而非誤導性的「可負擔 0 元」——凡個人化參數未設定，一律 fail-closed（不誤判為已達成/可負擔），不用 `0 >= 0` 這類在未設定時恰好為真的比較式。
- **自備款 bucket 口徑**：僅計入用途＝購屋且分類為活存／定存的資產市值（波動資產如股票不計入，避免市場波動影響「存夠了沒」的判斷）；若購屋 bucket 中仍混入其他分類資產，顯示組成警示，距目標購屋年愈近警示層級愈高（由提示升級為錯誤級）。
- **五條觸發條件**：定錨（主觀勾選）、收入達門檻、自備款達標、月付占比未超上限（三項系統依既有服務判定）、認知（主觀勾選）；五條全數達成才視為「可啟動購屋」，缺一即列出具體缺口（差多少金額／百分點）。主觀勾選即時持久化，不需按儲存按鈕。
- 「買房」獨立頁與「總覽」頁摘要皆呼叫同一組 `HouseService`/`AffordabilityService` 方法，確保兩處顯示的 bucket 進度％與觸發達成數在同一時點必然一致。

## 環境需求

- Python >= 3.12
- 一個 Turso 資料庫（雲端 SQLite，免費層即可）
- 一組 Google OAuth 2.0 用戶端（供 `st.login()` OIDC 登入）

## 機密設定

本專案不使用 `.env`，機密走 Streamlit 的 `st.secrets`。本機開發複製範本並填入實際值：

```bash
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
```

`secrets.toml` 已被 `.gitignore` 排除、絕不可進版控；雲端部署改用 Community Cloud 後台 Secrets UI 貼上相同結構。

| 設定鍵 | 必填 | 說明 |
|--------|------|------|
| `turso.database_url` | 是 | Turso 資料庫 URL（`libsql://...turso.io`），於 https://turso.tech 取得 |
| `turso.auth_token` | 是 | Turso 存取權杖，等同資料庫密碼 |
| `allowed_emails` | 是 | 允許登入檢視的 Google email 清單（陣列或逗號字串）；漏設＝不放行任何人 |
| `auth.client_id` / `auth.client_secret` | 是 | Google OAuth 2.0 用戶端憑證 |
| `auth.redirect_uri` | 是 | OIDC 回呼網址（本機 `http://localhost:8501/oauth2callback`、雲端為 `.streamlit.app` 對應網址，兩者都要登記到 Google） |
| `auth.cookie_secret` | 是 | session cookie 簽章用高熵隨機字串（自行產生） |
| `auth.server_metadata_url` | 是 | OIDC metadata，Google 固定為 `https://accounts.google.com/.well-known/openid-configuration` |

## 注意事項

- 財務資料完整存於 Turso；`secrets.toml` 內的 Turso 權杖等同資料庫密碼，外洩請立即至 Turso 後台 rotate。
- app 部署於公開 URL，存取控制僅靠 `st.login()` 登入＋email 允許清單；非清單內帳號登入後即被擋下，看不到任何資料。
- 舊版「項目間轉移」以覆寫寫入非股票端（會清掉當月市值、同月多次轉移不累加），現已改為累加；但舊版已覆寫的歷史紀錄不會自動修補，可從錄入頁「本月已存紀錄」表找出市值空白的月份手動補錄。
- Turso 免費單庫，建議定期以「匯出 CSV」備份；匯入還原僅支援空庫（目標庫非空會被拒絕，避免污染既有資料）。
- **已知環境事項**：`app.py` 開頭在 `import streamlit` 之前搶先設定 `os.environ.setdefault("ARROW_DEFAULT_MEMORY_POOL", "system")`，用意是規避 pyarrow 25 內建 mimalloc 配置器在 macOS arm64 的 thread-init segfault——顯示 DataFrame（`st.dataframe` / `st.data_editor`）觸發 pandas→Arrow 轉換時，曾實測整個 Python 進程 `EXC_BAD_ACCESS` 崩潰；停用 mimalloc、改用系統 malloc 後已驗證穩定。此設定必須早於 Streamlit（連帶 import pyarrow）之前才生效，故 import 順序看似不合慣例，維護者請勿因「風格統一」而移動或刪除這行。
- **本機開發踩坑**：未安裝 `watchdog` 套件時，修改 `views/*.py` 以外的模組（如 `src/asset_lab/` 下的檔案）後，僅重整瀏覽器不會生效——這些模組是被 `import` 進來、快取在 Python process 記憶體中，需重新啟動 `streamlit run app.py` 才會重新載入。建議開發時安裝 `watchdog`（`uv add --dev watchdog`）讓 Streamlit 自動偵測變更。
